# 剧本资产视频一条龙本地适配 PRD

## 1. 文档信息

- **产品名称**：剧本资产视频一条龙创作（本地适配版）
- **目标载体**：无限画布、Canvas Agent、Codex 本地工作区
- **文档状态**：需求草案，待评审
- **目标用户**：需要把创意或剧本整理为可执行视频生产流程的创作者

## 2. 背景与目标

即梦技能提供从创意/剧本到成片的分阶段工作流，但依赖即梦专属工具和云端资源 ID，无法直接在本地 Canvas Agent 中运行。本需求将其核心方法论适配为本地 Skill：由 Codex 负责文本规划和阶段推进，由无限画布负责节点、素材引用和生成结果组织，由用户在关键阶段进行确认。

### 目标

- 将创意或原始剧本转换为标准格式剧本。
- 将确认后的标准格式剧本自动放入无限画布，作为后续流程的起点。
- 自动提取角色、场景、道具等视觉资产并生成设计提示词。
- 将剧本拆分为用户选择的 5 秒、8 秒、10 秒或 15 秒分镜片段。
- 为每个片段生成运镜提示词并建立资产匹配表。
- 在确认节点后，将剧本、资产、分镜和生成结果组织到无限画布。
- 通过当前已配置的图片/视频/文本模型完成可替代的生成流程。

### 非目标

- 不复制或绕过即梦登录、积分、鉴权和风控。
- 不承诺直接调用 `dreamina_cli`、`seedance2.0_vip` 或即梦 `output_id`。
- 不在没有用户确认的情况下批量生成视频或消耗第三方额度。
- 不把本地浏览器数据改造成云同步数据。

## 3. 产品方案

### 3.1 运行方式

用户在 Canvas Agent 对话中输入创意或剧本，并选择本地 Skill。Skill 先完成标准格式剧本，用户确认后立即在无限画布中创建剧本文本节点和项目入口节点。此后所有阶段都必须在无限画布内进行：读取画布中的剧本节点，创建和更新资产、分镜、提示词、生成配置及结果节点，并将阶段状态写回画布。用户确认后才进入下一阶段，可随时回到画布中的上游节点修改。

无限画布是后续流程的唯一工作入口和状态来源；本地 Markdown 仅作为用户主动导出的交付副本，不作为流程继续执行的依据。

### 3.2 即梦工具的本地替代

| 即梦能力 | 本地适配方式 |
| --- | --- |
| `activate_skill` / `deactivate_skill` | Skill 内部阶段状态和上下文约束 |
| `write_file` / `present_files` | 改为画布导出/交付操作；仅在用户主动导出时生成本地 Markdown |
| `generate_form_for_info_collection` | 对话追问；后续可接入网页表单 |
| `dreamina_cli` | 无限画布现有图片/视频生成接口和生成配置节点 |
| `get_resource_status` | 复用当前生成任务状态查询和节点状态 |
| `dreamina_prompt_optimize` | 使用当前文本模型生成和优化提示词 |
| 即梦 `output_id` | 使用画布节点 ID、素材存储键和生成记录 ID |

## 4. 用户流程

1. 用户在 Agent 对话中输入原始创意、概要或完整剧本。
2. 系统判断为“创意扩写”“完整剧本无损拆解”或“格式标准化”。
3. 输出标准格式剧本，用户确认并选择整体视觉风格。
4. 系统在无限画布创建剧本文本节点和项目入口节点，并建立项目元数据。
5. 后续阶段只读取和写入画布：提取角色、场景、道具，创建资产提示词节点，用户确认是否生成设定图。
6. 按资产生成图片节点；用户逐项确认或要求重生成。
7. 用户选择分镜片段时长（5 秒、8 秒、10 秒或 15 秒）后，从画布剧本节点切割对应时长的分镜片段，创建分镜节点，用户确认完整性。
8. 为每个分镜节点生成运镜提示词和资产匹配关系，用户确认匹配结果。
9. 用户确认并发数量、画幅、时长和模型后，在画布中提交视频生成任务。
10. 将生成结果和阶段关系持续写回画布；最终可从画布导出完整 Markdown 交付副本。

## 5. 功能需求

### FR-01 原始内容模式判断

- 支持短创意、概要、完整剧本三类输入。
- 完整剧本模式必须保留原始台词、动作和分支，不得扩写或概括。
- 概要模式可以补充合理细节，但不得改变核心剧情和人物关系。
- 判断结果须在首个产物中明确展示，允许用户纠正模式。

### FR-02 标准剧本生成

- 一级标题表示幕和时间范围。
- 二级标题表示场次、地点、内外景、时间和时长。
- 画面行以“画面：”开头，包含景别和具体画面描述。
- 台词行标注角色名及必要状态说明。
- 场次之间使用分隔线，原始文本不得因排版被遗漏。
- 用户确认后，必须在无限画布创建一个完整的标准剧本文本节点；节点内容是后续所有阶段的唯一剧本来源。
- 创建剧本节点时保存原始输入、模式判断、视觉风格和项目 ID 等 metadata。

### FR-03 画布项目初始化

- 标准剧本确认后自动创建项目入口节点、标准剧本文本节点和阶段状态信息。
- 项目入口节点记录当前阶段、确认状态和关联节点 ID。
- 剧本节点与后续资产、分镜节点通过项目 ID 和来源节点 ID 关联。
- 初始化失败时不得进入资产提取阶段，并向用户显示可恢复的错误。

### FR-04 视觉资产提取

- 至少支持人物、场景、道具三类资产。
- 每个资产包含名称、来源段落、设计描述、设计提示词和状态。
- 关键设计信息缺失时再向用户提问，不为非关键细节反复追问。
- 资产可绑定到画布图片节点或用户提供的参考素材。
- 资产提取必须从画布中的标准剧本文本节点读取，不再以 Agent 对话草稿或本地文件为准。

### FR-05 设定图生成与确认

- 仅在用户明确确认后提交设定图生成。
- 每个资产生成结果独立关联，不覆盖其他资产。
- 支持单个资产重生成，并保留已确认结果。
- 生成失败时展示可读错误，不自动无限重试。
- 生成状态、提示词和结果必须写回对应画布节点。

### FR-06 分段时长与零损耗分镜切割

- 用户必须从 5 秒、8 秒、10 秒、15 秒中选择一个分镜片段时长。
- 分镜切割阶段开始前必须保存所选时长；未选择时长不得进入切割。
- 以用户选择的时长为目标片段，不把每个镜头强制拆成独立片段。
- 每段包含景别、画面描述和台词，台词应来自原始文本。
- 单段台词过长时在语义停顿处切分，不能删除或改写台词；较短时长应允许产生更多连续片段。
- 首段交代人物进入或到达当前空间的逻辑。
- 片段数量根据文本信息量决定，禁止为了固定数量截断内容。
- 分镜切割输入必须是画布中的标准剧本文本节点，输出为可独立编辑的分镜节点或分镜组。

### FR-07 运镜提示词与资产匹配

- 每个片段生成独立提示词和资产匹配列表。
- 保持核心空间连续，景别和运动方式有节奏变化。
- 单个微片段聚焦一个主角色，避免角色位置混乱。
- 提示词必须遵循已确认的角色设定，不自行增加关键动作。
- 匹配表未确认前不得提交视频生成。
- 运镜提示词和匹配关系必须写入画布节点，后续生成只能引用画布中已确认的节点。

### FR-08 视频生成

- 生成配置节点读取对应片段的提示词和参考图。
- 使用当前配置中的视频模型、画幅和时长，不硬编码即梦模型名。
- 视频时长默认沿用分镜阶段选择的 5 秒、8 秒、10 秒或 15 秒；如用户修改，必须重新确认并同步更新分镜节点。
- 提交前展示模型、并发数量、画幅、时长和预计外部额度影响。
- 用户确认后才提交任务；任务状态回写到对应视频节点。
- 生成结果失败时允许单片段重试，不影响已完成片段。
- 视频任务必须从画布中的分镜提示词和资产节点发起，不能只根据对话中的临时文本生成。

### FR-09 交付与恢复

- 用户可以主动从画布导出每个阶段产物或完整 Markdown 文件。
- 画布节点保存阶段状态、来源关系和生成记录。
- 刷新页面后必须从画布恢复已保存的阶段结果和确认状态。
- 用户可以从画布中最近一个未确认阶段继续，不重复生成已确认资产。
- 本地导出的 Markdown 被重新导入前，不得覆盖或改变画布中的项目状态。

## 6. 数据结构建议

```ts
type LocalVideoProject = {
  id: string;
  mode: "idea" | "script" | "format";
  rawText: string;
  visualStyle: string;
  scriptNodeId: string;
  projectNodeId: string;
  segmentDuration?: 5 | 8 | 10 | 15;
  stage: "script" | "assets" | "references" | "shots" | "prompts" | "generation" | "delivery";
  confirmations: Record<string, boolean>;
  assetIds: string[];
  shotIds: string[];
  exportPath?: string;
};
```

画布节点通过 metadata 保存 `projectId`、`projectNodeId`、`stage`、`sourceNodeId`、`sourceText`、`assetId`、`shotId`、`generationRecordId` 等关联信息。媒体本体继续使用项目现有的浏览器本地存储机制。`scriptNodeId` 指向确认后的标准剧本文本节点，任何后续阶段都必须沿该节点或其派生节点追溯来源。

## 7. MVP 范围

### 首期必须交付

- 一个可被 Canvas Agent 加载的本地 Skill。
- 标准剧本确认后自动落入无限画布的项目初始化流程。
- 七阶段流程的画布产物和确认门禁。
- 剧本、资产、分镜、提示词和状态写入无限画布节点。
- 通过现有画布工具创建文本节点、图片节点和生成配置节点。
- 图片/视频生成失败后的人工重试入口。

### 后续迭代

- 网页侧边栏的阶段进度和确认表单。
- 资产与分镜的可视化匹配编辑器。
- 批量任务并发控制和更细粒度的任务恢复。
- 针对特定视频服务的独立适配器，不放入通用 Skill 核心。

## 8. 验收标准

- 输入完整剧本后，输出文本可逐段回溯到原文，台词无静默删改。
- 用户未确认剧本、设定图、分镜或资产匹配时，流程不能越过对应阶段。
- 每个分镜都能追溯到源场次、角色资产和参考图节点。
- 选择 5 秒、8 秒、10 秒或 15 秒中的任一时长后，切割结果和视频生成参数保持一致。
- 刷新或重新打开画布后，已确认阶段和生成结果状态保持一致，且流程从画布继续。
- 标准剧本确认后，后续 Agent 操作不依赖原始对话草稿或本地 Markdown 文件。
- 使用任意已配置的视频模型都能生成请求，不依赖即梦专属字段。
- 生成失败只影响对应任务，用户可以单独重试。
- 最终 Markdown 能独立说明剧本、资产、分镜、提示词和结果关联。

## 9. 风险与限制

- 不同视频服务对参考图数量、接口格式和时长限制不同，需要由渠道配置决定。
- 本地 Skill 不能获得即梦云端技能的隐藏提示词、资产 ID 或私有工具权限。
- 长剧本可能超过模型上下文，需要按场次分批处理，但必须保留项目级索引。
- 画布节点被用户手动删除、复制或拆分后，可能破坏项目关系；需要显示来源关系和不可用状态。
- 浏览器本地存储被清理后，媒体结果可能无法恢复；交付 Markdown 不等于媒体已云端备份。
- 任何新增的超时、重试、大小或并发边界，都应在实现前单独确认默认值和失败处理。

## 10. 待确认决策

- 本地 Skill 的正式名称和触发词。
- 设定图和视频默认使用哪个已配置渠道。
- 视频生成结果是否自动落盘，还是只保存到浏览器本地素材库。
- 首期是否需要网页表单，还是先使用 Codex 对话确认。
