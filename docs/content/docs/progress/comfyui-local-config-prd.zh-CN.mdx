# 本地 ComfyUI 配置模块 PRD

## 1. 文档信息

- **产品名称**：本地 ComfyUI 配置模块
- **目标载体**：无限画布配置页、生图工作台、视频创作台、画布生成配置节点
- **文档状态**：首期图片工作流已实现，待人工测试
- **目标用户**：使用本机或局域网 ComfyUI 工作流进行图片、视频生成的创作者
- **交互原型**：`docs/prototypes/comfyui-config-prototype.html`

## 2. 背景与问题

当前项目已经支持“渠道 + 模型 + 自定义调用脚本”。用户可以通过脚本调用 ComfyUI，但需要自行编写 JavaScript、解析工作流、查找节点 ID，并手动处理任务轮询和图片下载。

这套方式适合熟悉代码的高级用户，不适合只希望导入 ComfyUI 工作流并填写参数的用户。与此同时，本地 ComfyUI 默认通常不需要 API Key，配置界面也不应把 API Key 设计成必填项。

本需求新增一个与现有渠道配置并列的“本地 ComfyUI”配置 Tab。用户导入 ComfyUI API 格式工作流后，通过节点输入绑定生成动态参数，最终把工作流注册为生图或视频模型，在现有工作台和画布中使用。

## 3. 产品目标

- 用户无需编写脚本即可添加本机或局域网 ComfyUI 服务。
- 用户可以导入一个 ComfyUI API 格式工作流并配置为可复用模型。
- 用户可以自定义需要填写的参数，并将参数绑定到指定节点输入。
- 用户可以在生图工作台、视频创作台和画布生成节点中选择这些工作流。
- 本地 ComfyUI 无 API Key 时可以正常调用；配置鉴权时可以按需发送 API Key。
- 现有 OpenAI、Gemini 和 ComfyUI 自定义脚本能力保持不变。

## 4. 非目标

- 第一版不修改 ComfyUI 源码，不安装 ComfyUI 插件或自定义节点。
- 第一版不执行用户导入 JSON 中的 JavaScript、Python 或其他代码。
- 第一版不承诺自动理解所有第三方自定义节点的语义。
- 不将本地 ComfyUI 结果默认上传到云端。
- 不删除或强制迁移现有 ComfyUI MiniMax H3、Z-Image 等自定义脚本。
- 不把 API Key 作为本地 ComfyUI 的必填配置。

## 5. 当前项目基线

### 5.1 当前配置页

现有配置页使用以下结构，新增模块应沿用该结构：

- 顶部是无限画布主导航。
- 内容区域使用居中的 `max-w-6xl` 布局。
- 配置功能通过横向 Tabs 分组。
- 渠道使用带边框的列表行展示。
- 渠道编辑使用 Ant Design `Drawer`。
- 脚本编辑使用 Ant Design `Modal` 和 CodeMirror。
- 主题支持浅色和深色，业务组件使用现有主题 Token 和 Stone 中性色。

### 5.2 现有能力复用

- 复用现有模型选择器和能力类型：生图、视频、文本、音频。
- 复用现有画布生成配置节点和生成记录。
- 复用现有图片、视频本地存储和生成状态处理。
- 复用现有配置导入、导出入口。
- 自定义脚本继续作为高级调用方式保留。

## 6. 核心概念

### 6.1 ComfyUI 服务

一个可以通过浏览器访问的 ComfyUI 实例，包含名称、Base URL、可选 API Key 和多个工作流。

默认示例：

```text
名称：ComfyUI 本地
Base URL：http://127.0.0.1:8188
API Key：留空
```

### 6.2 ComfyUI 工作流

一个从 ComfyUI 导出的 API 格式 JSON。工作流可以声明生成能力、可编辑参数和结果输出节点。

工作流不是单纯的模型名称，而是一个包含节点图、参数映射和输出映射的完整生成适配器。

### 6.3 工作流参数

工作流参数由用户定义，包含显示信息和节点绑定关系。参数必须绑定到节点 ID 与输入字段，否则只能显示在界面上，无法改变实际生成结果。

### 6.4 内置参数

系统提供以下常用参数的识别和默认绑定：

- 正面提示词
- 负面提示词
- 宽度
- 高度
- 批量数量
- Seed

## 7. 用户故事

- 作为本地 ComfyUI 用户，我希望输入地址后测试连接，不想填写无效的 API Key。
- 作为工作流创作者，我希望导入 API JSON 后直接复用现有 ComfyUI 工作流。
- 作为非程序用户，我希望把 `steps`、`CFG`、采样器等节点输入变成普通表单参数。
- 作为高级用户，我希望手动指定参数对应的节点和输入字段。
- 作为画布用户，我希望工作流参数可以随生成配置节点保存，重试时不丢失。
- 作为已有自定义脚本用户，我希望升级后原有模型和脚本继续可用。

## 8. 用户流程

### 8.1 添加服务

1. 用户进入“配置与用户偏好”中的“本地 ComfyUI” Tab。
2. 点击“新增服务”。
3. 填写服务名称和 Base URL。
4. API Key 可留空；如果服务配置了鉴权，用户再填写 API Key。
5. 点击“创建并测试”。
6. 系统调用 ComfyUI `/system_stats` 或 `/queue` 等只读接口测试连接。
7. 测试成功后保存服务；失败时显示网络、CORS、鉴权或地址错误。

### 8.2 导入工作流

1. 在服务编辑 Drawer 中点击“导入 JSON”。
2. 选择 ComfyUI 导出的 API 格式 JSON。
3. 系统校验 JSON 结构和节点输入格式。
4. 系统扫描常见节点并预填提示词、尺寸、采样器和输出节点。
5. 用户填写工作流名称和生成能力。
6. 用户在“输入参数”中增加、删除或修改参数。
7. 用户确认“输出节点”。
8. 用户运行测试，成功后保存工作流。

### 8.3 使用工作流

1. 用户在生图工作台、视频创作台或画布生成配置中打开模型选择器。
2. 选择“本地 ComfyUI / 工作流名称”。
3. 系统根据工作流参数定义动态渲染表单。
4. 用户填写提示词和自定义参数。
5. 系统提交 ComfyUI 任务并显示排队、运行、成功或失败状态。
6. 生成结果进入现有工作台记录或画布节点。

## 9. 功能需求

### FR-01 本地 ComfyUI 配置 Tab

- 配置页增加“本地 ComfyUI” Tab，位置与“渠道”“偏好设置”“提示词来源”等现有 Tab 并列。
- 页面显示服务列表、在线状态、Base URL、工作流数量和最近测试时间。
- 页面提供“新增服务”入口。
- 页面不新增独立侧边栏或独立品牌布局。
- 页面必须支持当前浅色和深色主题。

### FR-02 服务管理

- 支持新增、编辑、启用、停用和删除 ComfyUI 服务。
- 服务名称必填，Base URL 必须是 `http://` 或 `https://` 地址。
- Base URL 不允许包含 `/prompt`、`/history` 等具体接口路径。
- API Key 为可选字段。
- API Key 为空时，不发送 `Authorization` 请求头。
- API Key 非空时，按服务配置发送 `Authorization: Bearer <apiKey>`。
- 测试连接时明确区分连接失败、CORS 失败、鉴权失败和接口不存在。
- 删除服务前提示该服务关联的工作流数量。
- 删除服务不会删除已经加入画布或“我的素材”的历史结果。

### FR-03 工作流导入

- 支持导入 ComfyUI API 格式工作流 JSON。
- 第一版明确提示用户不要导入普通界面保存格式作为 API 工作流。
- 导入后校验顶层节点 ID、`class_type` 和 `inputs` 字段。
- JSON 无法解析、不是对象、节点缺少必要字段时显示明确错误。
- 导入失败不得覆盖服务中已有工作流。
- 工作流原始 JSON 保存在浏览器本地，不发送到第三方服务。
- 工作流可以重新导入，重新导入前展示会覆盖当前节点图的提示。

### FR-04 节点识别

- 自动识别常见内置节点：
  - `CLIPTextEncode`：正面提示词、负面提示词。
  - `EmptyLatentImage`：宽度、高度、批量数量。
  - `KSampler`：Seed、Steps、CFG、Sampler、Scheduler。
  - `LoadImage`：参考图输入。
  - `SaveImage`、`PreviewImage`：图片输出。
- 识别结果允许用户修改，不把自动识别结果视为不可变配置。
- 同一参数不能绑定多个输入，除非明确选择“同步写入多个输入”。
- 已被节点连线占用的输入默认不列入可编辑目标。
- 未识别的节点仍保留在原始工作流中，不能静默删除。

### FR-05 参数定义

- 用户可以新增、删除和编辑工作流参数。
- 参数必须包含稳定的机器名 `key` 和用户可见的 `label`。
- `key` 只能包含字母、数字、下划线和短横线，且同一工作流内不能重复。
- 支持以下类型：
  - 单行文本。
  - 多行文本。
  - 数字。
  - 下拉选项。
  - 开关。
  - Seed。
- 数字类型支持默认值、最小值、最大值和步进值。
- 下拉选项支持选项值和显示名称。
- 参数支持“必填”和“默认值”。
- 正面提示词默认必填；负面提示词、尺寸、Seed 等由工作流决定是否必填。
- 参数排序决定它们在生成设置面板中的显示顺序。

### FR-06 参数绑定

- 每个参数至少绑定一个节点 ID 和输入字段。
- 界面显示“参数 -> 节点 -> 输入字段”的完整关系。
- 支持字符串、数字、布尔值和枚举值的基本类型转换。
- 输入节点不存在、输入字段不存在或类型不匹配时不能保存。
- 提示词参数写入字符串字段时不得被自动转义成 JSON 字符串文本。
- width、height、steps、CFG 等数字参数提交前必须转换为数字。
- Seed 选择“随机”时，每次提交生成新的合法整数；选择固定值时保持固定值。
- 保存前显示未绑定参数、重复 key 和无效节点输入错误。

### FR-07 输出节点

- 用户必须选择至少一个输出节点。
- 图片工作流支持 `SaveImage` 和 `PreviewImage` 类型输出。
- 视频工作流支持已配置的视频输出节点或明确的输出文件类型。
- 输出配置包含节点 ID、输出类型和文件扩展名规则。
- 测试成功后保存最近一次输出节点和测试时间。
- history 已完成但没有符合输出类型的结果时显示明确错误。

### FR-08 工作流模型注册

- 保存后的工作流作为一个可选模型出现在对应能力的模型选择器中。
- 工作流模型使用稳定的内部 ID，例如：

```text
comfyui::<serviceId>::<workflowId>
```

- 显示名称包含服务名称和工作流名称，避免多个服务中同名工作流混淆。
- 生图工作流只能出现在生图模型选择中，视频工作流只能出现在视频模型选择中。
- 删除或停用服务后，关联工作流不再作为可选模型，但历史记录仍保留原名称和参数。
- 现有渠道模型和自定义脚本模型的选择逻辑不变。

### FR-09 动态生成设置

- 选择 ComfyUI 工作流后，生图或视频设置面板根据参数定义动态渲染输入控件。
- 内置正面提示词、负面提示词、width、height 等现有设置可以映射到工作流参数。
- 工作流自定义参数显示在现有设置面板的扩展区域，不覆盖现有通用字段。
- 参数修改后立即更新当前生成配置，但只有点击生成时才提交请求。
- 画布配置节点保存工作流 ID、服务 ID 和完整参数值。
- 重试时从画布节点 metadata 或生成记录恢复原工作流和参数。
- 工作台历史记录保存工作流名称和生成参数摘要。

### FR-10 ComfyUI 执行器

- 提交任务使用 ComfyUI `/prompt` 接口。
- 任务提交成功后记录 `prompt_id`。
- 通过 `/history/{prompt_id}` 查询状态和输出。
- 图片结果通过 `/view` 下载并交给现有图片存储流程。
- 参考图场景通过 `/upload/image` 上传后写入对应节点输入；首期可以先支持文生图。
- 取消生成时调用 `/interrupt`，同时停止浏览器轮询。
- 执行器不得把固定超时、重试次数或并发上限静默改成新的行为边界；这些参数需要单独评审后实现。
- ComfyUI 节点报错时显示节点 ID、节点类型和错误信息。

### FR-11 配置持久化与导入导出

- 服务配置、工作流 JSON、参数定义和绑定关系保存在浏览器本地。
- 工作流 JSON 和服务列表属于业务数据，优先使用 IndexedDB / `localforage`，不使用 localStorage 保存大 JSON。
- 现有配置导出文件增加 `comfyui` 数据段。
- 导入配置时恢复 ComfyUI 服务、工作流和参数定义。
- 导入错误配置时不得覆盖当前有效配置。
- 导出文件包含 API Key 时，界面继续显示现有安全提示。
- 删除服务或工作流时同步清理配置索引，不删除已有生成记录中的快照。

### FR-12 安全与权限

- 工作流 JSON 在浏览器端解析和校验，不执行其中的脚本字段。
- 服务请求只发送到用户配置的 Base URL。
- 页面明确提示浏览器直连本地服务需要配置 CORS。
- 本地 ComfyUI 无 API Key 时不发送空的 Bearer 头。
- API Key 仅保存在当前设备配置中，不上传到项目后端或第三方统计服务。
- 安装第三方 ComfyUI 节点、修改 ComfyUI 启动参数和访问远程服务由用户自行确认。

## 10. 数据结构建议

建议新增独立的 ComfyUI 配置域，不把完整工作流 JSON 直接塞入现有 `AiConfig` 的 localStorage 字段。

```ts
type ComfyUiService = {
  id: string;
  name: string;
  baseUrl: string;
  apiKey?: string;
  enabled: boolean;
  lastTestedAt?: string;
  lastTestStatus?: "success" | "failed";
  workflows: ComfyUiWorkflow[];
};

type ComfyUiWorkflow = {
  id: string;
  name: string;
  capability: "image" | "video";
  workflow: Record<string, ComfyUiNode>;
  parameters: ComfyUiParameter[];
  outputs: ComfyUiOutputBinding[];
  createdAt: string;
  updatedAt: string;
};

type ComfyUiParameter = {
  key: string;
  label: string;
  type: "text" | "textarea" | "number" | "select" | "boolean" | "seed";
  required: boolean;
  defaultValue?: string | number | boolean;
  placeholder?: string;
  min?: number;
  max?: number;
  step?: number;
  options?: Array<{ label: string; value: string | number }>;
  bindings: ComfyUiInputBinding[];
};

type ComfyUiInputBinding = {
  nodeId: string;
  inputKey: string;
  valueType: "string" | "number" | "boolean" | "enum";
};

type ComfyUiOutputBinding = {
  nodeId: string;
  type: "image" | "video";
  filenameKey?: string;
};
```

模型选择器只保存工作流引用 ID，不把整份工作流 JSON 放进画布节点。画布节点保存生成时使用的工作流快照摘要和参数值，保证工作流后来被编辑或删除后，历史记录仍可解释。

新增 Tab 后沿用当前配置页，不新增侧边栏：

```text
配置与用户偏好

管理本机或局域网 ComfyUI 服务，并将 API 工作流注册为可选择的生图 / 视频模型。

ComfyUI 服务                                      [新增服务]

┌──────────────────────────────────────────────────────────┐
│ ⌘  ComfyUI 本地   [在线]                                  │

└──────────────────────────────────────────────────────────┘
```

### 11.2 服务编辑 Drawer

沿用现有渠道编辑的右侧 Drawer：

- 服务名称。
- Base URL。
- API Key（可选）。
- 工作流列表。
- 导入 JSON。
- 测试连接。
- 保存和取消。

### 11.3 工作流编辑 Modal

沿用现有脚本编辑器的宽 Modal，内部使用横向 Tabs：

```text
工作流    输入参数    输出节点    测试保存
```

- “工作流”：名称、能力、API JSON 和节点概览。
- “输入参数”：参数列表、参数类型、默认值、节点输入绑定。
- “输出节点”：选择图片或视频输出节点。
- “测试保存”：测试提示词、最小参数、请求日志和测试结果。

界面使用项目现有的深色 / 浅色主题、边框列表、扁平按钮和 Ant Design 控件，不使用独立侧边栏、荧光色品牌色或大面积装饰卡片。

## 12. 技术方案

### 12.1 前端模块

```text
web/src/
├─ types/comfyui.ts
├─ stores/use-comfyui-store.ts
├─ services/comfyui/
│  ├─ comfyui-client.ts
│  ├─ workflow-parser.ts
│  ├─ workflow-runner.ts
│  └─ workflow-schema.ts
└─ components/layout/
   ├─ comfyui-config-panel.tsx
   ├─ comfyui-service-editor-drawer.tsx
   ├─ comfyui-workflow-editor-modal.tsx
   └─ comfyui-parameter-editor.tsx
```

### 12.2 服务调用

```text
创建任务：POST  {baseUrl}/prompt
查询任务：GET   {baseUrl}/history/{prompt_id}
读取图片：GET   {baseUrl}/view
上传参考图：POST {baseUrl}/upload/image
停止任务：POST  {baseUrl}/interrupt
```

请求头规则：

```ts
const headers = apiKey
  ? { Authorization: `Bearer ${apiKey}` }
  : {};
```

调用 ComfyUI 前，执行器复制工作流 JSON，按照参数绑定写入节点输入，不修改用户保存的原始工作流。

### 12.3 模型选择器集成

新增 ComfyUI 工作流模型选项适配层，将工作流模型合并到现有能力筛选中。已有 `channels` 和 `ChannelModel` 数据不删除，避免影响已有配置和自定义脚本。

- `/queue` 队列管理、任务取消和更细的状态诊断。
- 从现有自定义脚本生成工作流配置。

## 14. 验收标准

- 在当前配置页可以进入“本地 ComfyUI” Tab，页面布局、主题、按钮和列表风格与现有配置页一致。
- 新增服务只填写 `http://127.0.0.1:8188` 和名称即可完成保存，不要求 API Key。
- API Key 为空时，浏览器请求中没有 `Authorization: Bearer` 空值请求头。
- API Key 非空时，请求带正确的 Bearer 头。
- CORS 未开启时，界面显示需要配置 CORS 的明确提示，而不是只显示“请求失败”。
- 导入合法 API 工作流后，节点数量、工作流名称和生成能力可以显示并保存。
- 导入非法 JSON 或普通界面工作流格式时，不覆盖已有工作流，并显示可读错误。
- 自动识别或手动绑定正面提示词、负面提示词、宽度和高度后，实际提交的工作流节点输入值正确。
- 新增一个 `steps` 或 `CFG` 参数后，参数可以在生成设置中填写，并写入对应节点输入。
- 重复参数 key、缺失节点和类型不匹配时不能保存。
- 工作流测试成功后，可以从 `/history` 找到配置的输出节点，并通过 `/view` 得到图片。
- 工作流模型只出现在对应的生图或视频能力选择器中。
- 画布刷新后，工作流 ID、参数值和生成记录仍可恢复。
- 删除服务不会删除既有画布节点、图片、视频或历史生成记录。
- 现有 OpenAI、Gemini 和自定义脚本模型选择与调用行为不回归。
- 配置导出和重新导入后，ComfyUI 服务、工作流和参数绑定保持一致。

## 15. 风险与限制

- ComfyUI 自定义节点输入结构差异较大，自动识别只能覆盖常见节点，必须保留手动绑定入口。
- 普通界面工作流和 API 工作流格式不同，首期需要明确拒绝不支持的格式。
- 浏览器直连依赖 CORS，用户可能误把 CORS 问题判断为服务离线。
- 某些 ComfyUI 部署使用反向代理鉴权，API Key 传递方式可能不是 Bearer，需要后续增加自定义请求头配置。
- 工作流 JSON 可能很大，必须使用 IndexedDB / `localforage`，避免 localStorage 超限。
- 用户删除或修改工作流后，历史任务仍需要保留当时的工作流名称和参数快照。
- 不同输出节点的 history 数据结构可能不同，需要通过输出类型适配并给出诊断信息。
